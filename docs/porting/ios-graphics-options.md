# iOS Graphics and Effects option audit

Scope: all 44 controls on the Graphics (17) and Effects (27) pages generated by
`GeneralsMD/Code/Tools/optionsmenu_layout.py`. This reviews the current SDL/Metal
port, its preference handling, consumers, platform guards and effect interactions.
It does not establish that every effect looks correct on an iPhone or iPad.

**Connected** means the saved choice has a game/rendering consumer in the iOS
build. **Conditional** means hardware, assets, scene type or another setting can
prevent activation. **Unavailable** means the necessary rendering path is absent;
the menu disables or hides the control and preserves its saved choice.

## Fixes and evidence

All 44 controls now have a connected or capability-dependent implementation:
17 connected and 27 conditional. Capability or allocation failure can still disable
an individual path; the menu and diagnostic messages report that result. This is
source integration, not a claim that every option has been visually validated on
every iPhone/iPad.

The new device log from `31177f8d` supplied two additional concrete failures:

- Bootstrap selected `Documents/UserData`, but the engine used the desktop
  `Library/Application Support` directory. Startup now resets the early directory
  cache after UIKit configuration and migrates missing legacy entries to Documents
  using same-container renames. Existing Documents files win; conflicting legacy
  files and symlinks are retained. `[IOS_USER_DATA]` reports migration and selection.
- The fullscreen desktop-mode path left an unknown colour format and requested
  unsupported D32 depth, then retried without stencil. iOS now selects formats
  through its UIKit-owned window, allowing the existing D24S8-first probe. This
  addresses the logged `stencil_available=0` and the destination-alpha format
  required by original water effects. A device run must confirm the chosen formats.

That log also shows saved Reforged lighting/smoke values alongside active Classic
mode and `classic_selected=1` on every Accept. Choosing a Reforged-only control now
unticks Classic for the next start, without applying a preset to other settings.
The Graphics page displays a restart notice; the current runtime mode stays fixed.

- Saved lighting/smoke choices now drive both display and change detection during
  a Classic run. This fixes menu reopen and changing back to the forced values.
  The additional startup/mode fixes above address the concrete device-log evidence;
  the resulting on-device behavior still needs validation.
- `[IOS_OPTIONS]` records selected, saved, loaded and active values for those
  choices, including the file path and I/O errors. `[GRAPHICS_CAPS]` records the
  renderer's supported subset. A requested flag is not evidence of rendered pixels.
- Unsupported catalog controls keep their preferences on Accept/Defaults.
  Capability checks only disable controls and preserve match restrictions.
- Removed back-buffer-only AO gates: the main scene redirected by Glow is a
  valid opaque scene target. Reflection/custom scene exclusions remain.
- MSAA, HDR, water and heat controls query the native renderer; supported MSAA
  choices are capped to the scene colour/depth hardware intersection.

Additional renderer settings outside these 44 generated controls: the saved VSync
request now configures the SDL swapchain during creation/reset. Uncapped mode is
capability-dependent; `[SDL_PRESENT]` reports the actual mode and fallback. The
post-chain string can select native FXAA/sharpen filters, but the iOS default
omits both to avoid their full-resolution sampling cost. Shared bloom, native AO
and native tone/colour grading have independent paths. An explicit `-dx11post`
chain can opt back into either filter. Filtering preserves alpha, clamps to the
world viewport and precedes UI. MSAA skips FXAA and selects a mild softening
amount; memory pressure pauses optional filters. `[SDL_POST]` reports requested
and selected passes. See [port status](ios-feature-audit.md).

The iOS Resolution dropdown selects the internal world-render size while the
display, swapchain, and UI remain at native resolution. Presets are Native,
75%, two-thirds (shown as 67%), and 50%; dimensions are calculated from the
device display size, preserving its aspect ratio. On an iPhone 16 Pro Max
(2868x1320), these are 2868x1320, 2151x990, 1912x880, and 1434x660. The world,
shadowed geometry, and supported scene effects render into the selected scene
target, which is composed before native-resolution UI. The selected scale is
saved as `RenderScale` in `Options.ini`. On iOS, the display size is taken from
the device rather than a previously saved `Resolution` value.

## Validation limits and device checks

`test_graphics_preferences.py` exercises the actual save logic, both platform
capability branches and the actual AO device/frame dispatch with mocked GPU
boundaries. The dispatch regression uses a scene texture different from the back
buffer, checks shroud forwarding, and retains excluded-view/failure behavior.
`test_sdl_ao` separately compiles production shaders and checks actual Metal pixel
results for AO, haze, atmosphere, hemisphere lighting and team glow. It checks
transparent disabled passes, near/far ground, shroud, submerged ground, viewport
origin/depth range, sky, alpha preservation and target resizing.
`test_ios_graphics_startup.py` checks migration conflicts, repeatability and the
iOS window/stencil selection branch; `test_userfolders` checks cache reselection.
These do not validate every real map, asset or option combination.

On the new IPA, use one map and camera, change one supported setting at a time,
Accept, then reopen Options to check persistence. Restart for Classic Graphics,
filtering, smoke thickness and particle bounce; load a new map for lighting,
trees, sway, scaffolding and caster changes. Compare AO with Glow off/on. Check
volumetric smoke during an actual smoke event and stencil markers with an
occluded unit. Preserve the current and previous stderr logs across the restart.


## Firelight, heat haze and the `a7035f1b` device log

The new log confirms `Documents/UserData` selection and `stencil_available=1`,
D24S8 depth (`75`), and a normal exit. It still loads a legacy Options.ini with
`LightingStyle=1`, `VolumetricSmokeShadows=yes` and no `ClassicGraphics` entry.
On iOS, a missing mode now resolves to Reforged when either of those explicit
opt-ins exists. The archive mount and option loader use the same resolver.
Explicit Classic choices and empty/new files retain their prior behavior. Accept
writes the mode even when unchanged; `[IOS_OPTIONS] phase=mode` names its source.

`[SDL_FIRELIGHT] ready` identifies native opaque fire-light resource setup. The
pass runs before AO/atmosphere/water/particles; destination-scaled additive RGB
preserves black shroud and destination alpha and caps the gain at 75 percent.
The follow-up opaque pass also consumes the shared dynamic/headlight lists;
translucent draws retain vertex lights. Failure disables capability with its reason.

`[SDL_HEAT] ready size=...` identifies the immutable GPU background. Only the
scoped smudge stage-0 binding may substitute that snapshot; other render-target
feedback is still refused. Capture flushes prior scene/particle work, refreshes
for each smudge pass and resizes to the actual target. No CPU readback is used in
production. Host tests check the actual copy/readback, immutable contents, refresh,
odd dimensions and resizing; sanitizer tests cover binding guards and cleanup.

Synthetic fire-light checks cover zero lights, range, surface direction, twelve
strong lights, sky, black shroud, alpha, cropped viewports and viewport depth range.
SPIR-V/MSL compilation and host GPU evidence do not establish game-map appearance
or iPhone frame time; those still require device validation.

## Remaining batch validation

The new batch adds soft-particle fades, flame treatment, object cloak/reveal/EMP/
outage effects, client-only building collapse, headlights, water/foam, HDR and
MSAA. HDR tests check floating-point radiance, alpha, grading, cropped viewports,
CPU compatibility and HUD sequencing. MSAA tests check edge coverage, independent
alpha-tested depth (including a second-stage mask), redirected targets, HDR/UI
composition, partial depth clears and transient-cache recreation.

The prior batch's Metal run exposed mixed integer-load/sampled-texture binding
collisions. Native shader generation now pairs integer reads with explicit same-
slot samplers at texel centres. Seventeen production variants compile to SPIR-V
and MSL with unique texture bindings locally. The rerun of ARM64 workflow 41623320860 passed these native effects and full
POSIX GPU draw checks and packaged an IPA at `33b49198`. HDR/MSAA and the newer
memory-pressure response still need their own ARM64 validation.

MSAA increases memory and depth geometry work; HDR doubles scene-colour storage.
Measure both on the target iPhone/iPad before increasing defaults. Neither feature
changes the default request. Building collapse is a separate Display-page control.

The supplied `33b49198` device run initialized Reforged effects and persisted
choices but ended after three low-memory warnings. A real warning now pauses
AO, atmosphere, per-pixel lighting and FFT caches, and turns off active MSAA for
the renderer session. Repeated warnings retain required scene copies instead of
releasing/rebuilding them. Preferences stay saved for the next device creation.
Runtime memory samples report footprint, headroom and sampled peak; they do not
establish the actual peak or prove a Jetsam termination.

## Projectile and Classic shoreline regression follow-up

The user reports artillery/tank visuals disappeared after the new particle batch,
while Modern water blends but Classic water cuts off. Native sorted billboards
previously enabled contact fading for every quad. Weapon trails attached to an
opaque shell can sample that shell's own depth and lose their glow. The sorting
metadata now carries contact-fade eligibility independently of quad geometry;
iOS WEAPON_TRAIL systems retain their authored contribution. Smoke and other
eligible billboards keep contact fades. Batching compares/hashes the new flag.

Classic shoreline tiles were not regenerated when smoothing was enabled after
map preparation. A render-boundary refresh now rebuilds the tile list and alpha
LUT on initial use and settings changes. Bounded IOS_PROJECTILE_MODEL,
IOS_PROJECTILE_PARTICLES and IOS_SHORELINE diagnostics distinguish model
submission, particle count and shoreline availability on the next device run.
Actual map appearance still needs device evidence.

The expanded audit also found that headlight collection still required
Direct3D11_Is_Active, which always returns false on iOS. It now uses the native
per-pixel-light capability, allowing the previously ported lighting pass to
receive eligible vehicle beams. Memory-pressure fallback still omits that pass.

The smoke-lighting follow-up also enables iOS's native post-shadow glow path,
which had retained a Linux-only guard. Additional combined smoke-glow/soft-depth
vertex and pixel variants bring the production compilation check to 23 variants.
